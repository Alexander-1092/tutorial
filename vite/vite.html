Сборщик Vite

Введение

Vite - это инструмент сборки, созданный для обеспечения быстрого и бережливого процесса разработки современных веб-проектов. Состоит из двух частей сервер разработки и сборка(билд) для сайтов.

Сервер разработки отвечает за производительность (мгновенное обновление), конвертацию файлов (из одного формата в другой), хостинг сайта (отображение результата). Основывается на технологии esbuild.

Сборка отвечает за оптимизацию финального кода: минификация, разбивка на части (разбивка одного большого js-файла на несколько меньших (чанков)), удаление мёртвого кода (код который нигде не используется). Основывается на технологии Rollup.

Установка

Для установки Vite на чистый проект используем команду:

npm create vite@latest

Если проект уже существует то:

npm install -D vite

В процессе установки появится ряд запросов:

  • назвать имя проекта (если назвать, то появится папка с именем проекта, если вам этого не нужно то ставим точку)
  • дать имя Package name (это имя которое будет отображаться в настроечных файлах).
  • Выбрать фреймворк - Select a framework. Если работает без фреймворка, то выбираем Vanilla.
  • Select a variant: js или typescript
  • Install with npm and start now? выбираем да.

В результате установки в проекте появится ряд папок и файлов:

  • node_moduls (библиотеки, здесь находится сам сборщик и маленькие библиотеки)
  • publick (статические файлы, которые не нужно обрабатывать (иконки, шрифты))
  • src и assets (здесь находится исходный код вашего проекта. Сразу после создания там будут шаблонные файлы, их удаляем),
  • index.html (главная страница, входная точка)
  • package-lock.json (версии каждой установленной библиотеки),
  • package.json (конфигурация проекта),
  • gitignore (можете заметить, что среди игнорируемых файлов стоит папка дист, ее можно исключить оттуда если хотите развернуть проект на сервере гитхаба, но как правило используется ci|cd).

После установки также запустится локальный сервер.

В файле html найдете строку <div id="app"></div>

Данный див используется для фреймворков, если пишется на Vanilla JS (чистый js), то данный див можно удалить.

Также в html-файле бужет подключен js файл с типом модуль.

В package.json появляются следующие скрипты: 

"dev": "vite",
"build": "vite build",
"preview": "vite preview"

dev для разработки, build для конечной сборки (не запускает локальный сервер), preview для обзора сборки.

Стили

Подключение файла со стилями нужно в js файле, который подключен в html. В нем импортируем стили import "./css/style.css";

Если мы работает с SCSS, то вначале устанавливаем его в проекте npm install sass --save-dev. Далее создаем scss-файл, и импортируем его в js файл. Больше ничего делать не нужно, конвертацию сборщик проведет сам.

Если у вас несколько файлов со стилями, то необходимо импортировать их в один файл стиля, и уже его импортировать в js файл. Это считается хорошей практикой, однако если вы подключите каждый файл стиля отдельно в js, то они всё равно будут работать, но могут возникнуть проблемы (дублирование кода, нарушение порядка подключения, а также нарушение связи с переменными, миксинами, функциями, если они находятся в разных файлах).

В отличие от файлов стилей, js-файлы не нуждаются в промежуточном файде-сборщика их можно сразу импортировать в главный js-файл, если это модульные приложения, либо если это независимые скрипты (стороние библиотеки, плагины, виджиты), то их подключаем в html.

Многостраничность

Если наш проект содержи несколько html-страниц. В этом случае, для каждой html-страницы подключаем свой js-файл с типом модуль.

Далее создаем конфиг файл для сборщика с названием vite.config.js. Пишем настройки: 

import { defineConfig } from "vite";
import { resolve } from "path";

export default defineConfig({
  root: ".",
  build: {
    outDir: "dist",
    rollupOptions: {
      input: {
        main: resolve(__dirname, "index.html"),
        page_two: resolve(__dirname, "html", "page-two.html"),
      },
    },
  },
  resolve: {
    alias: {
      "@": resolve(__dirname, "./src"),
      "@scss": resolve(__dirname, "./src/scss"),
    },
  },
});

import { defineConfig } from "vite"; это импорт функции defineConfig из пакета vite. Эта функция нужна для создания конфигурации с автодополнением (IntelliSense) в редакторе кода. Она не меняет поведение, но делает код удобнее для разработки. Если вам это не нужно, то можно работать напрямую export default { ... }.

import { resolve } from "path"; - импорт функции resolve из встроенного Node.js-модуля path. resolve склеивает пути в правильный абсолютный путь для вашей операционной системы.

export default defineConfig - экспорт объекта конфигурации. При запуске сборщик ищет файл конфига и читает его экспорт по умолчанию.

root: ".", - указывает корневую директорию проекта. Нужно чтобы сборщие смог найти index.html. Если не указать, то сборщик будет искать index.html в текущей папке.

build: - раздел настроек для зборки проекта

outDir: "dist", - папка, куда будет собрана готовая версия проекта.

rollupOptions: - Настройки для Rollup (движок vite, который используется для сборки продакшн-версии )

input: здесь описываются все точки входа (html-страницы). По умолчанию есть index.html, если есть несколько страниц, то указываем путь до каждой из них.

main: resolve(__dirname, "index.html") - первая точка входа. main - произвольное имя, которое будет использоваться в названии файлов. В resolve указывается полный путь к файлу. __dirname - переменная, которая содержит текущий путь к папке проекта.

page_two: resolve(__dirname, "html", "page-two.html"), - вторая точка входа (вторая html-страница).

resolve: - раздел настроек путей к файлам. Указывает сбощику как и где искать файлы.

alias: - настройка псевдонимов для путей. Позволяет использовать короткие имена вместо длинных

"@": resolve(__dirname, "./src"), - создаем алиас для папки src. @ теперь можно использовать как часть пути. Алиасы не работают в html.

"@scss": resolve(__dirname, "./src/scss"), - алиас для папки scss. Если вы не используете алиасы, то можете удалить весь раздел, он не обязателен.

Изображения

При использовании изображении в css\scss, не нужно делать дополнительные действия. Достаточно обычной ссылки. Но если изображение вставляется в html-файл, то правильней будет импортировать изображение в js, и там подключить его к нужному элементу. 

import img from "@/assets/img/img2.jpg";
document.querySelector(".cute").src = img;

Важно: импорт изображения необходим, потому что сборщик не анализирует строки в JavaScript. Он анализирует только импорты.

Минификация изображения

Для минификации изображения нужно установить три пакета:

  1. vite-plugin-image-optimizer
    • Подключается к процессу сборки Vite
    • Ищет изображения в вашем проекте
    • Передает их на обработку в sharp и svgo
    • Сохраняет оптимизированные изображения в папку dist
  2. sharp (основной движок для растровых изображений)
    • Конвертирует изображения в разные форматы (JPEG, PNG, WebP, AVIF)
    • Изменяет размер, обрезает, поворачивает
    • Сжимает изображения с настройками качества
  3. svgo (оптимизатор SVG)
    • Удаляет лишние теги и атрибуты
    • Объединяет стили
    • Упрощает пути (paths)
    • Удаляет комментарии, пустые группы, скрытые элементы
    • Уменьшает размер SVG без потери качества

Общая команда: npm install vite-plugin-image-optimizer sharp svgo -–save-dev

В конфиге импортируем модуль

import { ViteImageOptimizer } from "vite-plugin-image-optimizer";

В разделе плагинов, подключаем его

plugins: [ViteImageOptimizer()],

Можно указать отключение минификации в режиме разработки: 

plugins: [
  ViteImageOptimizer({
    disable: process.env.NODE_ENV !== "production",
  }),
],

Также можно прописать настройки сжатия для каждого формата отдельно. Без этого изображения сжимаются по стандартным настрйокам: 

plugins: [
     ViteImageOptimizer({
     // Качество для разных форматов
     png: {
       quality: 80,
     },
     jpeg: {
       quality: 80,
     },
     jpg: {
       quality: 80,
     },
     webp: {
       lossless: false,
       quality: 80,
     },
     avif: {
       quality: 70,
     },
     // Настройка SVGO для SVG-иконок
     svg: {
       multipass: true,
       plugins: [
         {
           name: "preset-default",
           params: {
          overrides: {
               removeViewBox: false, // Сохраняем viewBox
              },
            },
          },
        ],
      },
     disable: process.env.NODE_ENV !== "production",
    }),
 ],

Видео

Если мы используем видео в проекте, и оно находится в папке assets/video, то такой файл подключаем также как и изображение (импортируем в js, и через атрибут src подключаем к элементу). Если видео-файл находится в папке public или мы используем минификатор видео, то отдельно импортировать через js не нужно.

Минификация видео

Плагин - vite-plugin-optimize-videos

Команда: npm install -D vite-plugin-optimize-videos

Импортируем модуль в конфиг: import { optimizeVideos } from "vite-plugin-optimize-videos"

Вставляем в настройку плагинов optimizeVideos({}),

При необходимости можно указать степень сжатия видео 

optimizeVideos({
    quality: 25,
}),
