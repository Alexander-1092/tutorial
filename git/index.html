GIT

Git — это система контроля версий. С помощью Git можно создавать различные версии своего кода, просматривать историю изменений проекта и восстанавливать предыдущие версии кода.

Установливается Git с официального сайта. После установки появится терминал Git Bash.

*Терминал - это программа, которая позволяет пользователю взаимодействовать с компьютером с помощью текстовых команд.

Настройка

Перед началом работы нужно настроить имя пользователя и почту. Для настройки имени вводим: git config --global user.name ваше_имя

--global - это флаг (иногда называется опция), которое говорит о том что команда будет выполненна на глобальном уровне.

Аналогичная команда для электронной почты:git config --global user.email адрес вашей почты

Чтобы проверить введенные данные, используйте команду: git config --global --list Эта команда выведет список всех глобальных настроек Git.

Файловые команды

Существует два способа указать путь к папке/файлу, это абсолютный и относительный путь. Абсолютный путь — это полный, уникальный адрес к файлу или папке, начинающийся от корневой директории. Относительный путь — это адрес относительно текущего местоположения.

Команда Что делает
pwd Узнать полный путь к текущей папке
cd название_папки Перейти в выбранную папку
cd .. Переместиться на одну папку назад
cd / Переместиться в корневую папку
cd - Вернуться к предыдущей рабочей папке
cd ~ Перейти в домашнюю папку пользователя
ls Показать файлы и папки в текущей директории
start . Открыть текущую папку в файловом менеджере
code . Открыть текущую папку в VS Code
touch index.html Создать файл index.html
mkdir project Создать папку с именем project
rm имя_файла Удалить файл
rmdir имя_папки Удалить пустую папку

Создание репозитория

Создать репозиторий можно двумя способами:
- Создать репозиторий на вашем компьютере (локально), а затем соединить его с удаленным репозиторием на GitHub;
- Создать удаленный репозиторий на GitHub, а затем клонировать его на ваш компьютер.

Создать локально:

  1. Вводим команду git init
  2. Создаем удаленный репозитрий на ГитХабе
  3. Связываем локальный репозиторий с удаленным git remote add origin [ссылка на репозиторий]
  4. Связываем локальную ветку с удаленной и отправлем с неё данные: git push -u origin main

*origin — это не команда, а имя основного удалённого репозитория. Оно может быть любым, но принято называть именно так

*Флаг -u это сокращение от --set-upstream

Создать удаленно:

  1. Создаем репозиторий на гитхабе. Чтобы репозиторий не был полностью пустым, рекомендуется отметить опцию создания файла `README.md`. Этот файл используется для описания проекта
  2. Нажимаем нопку < > Code и копируем ссылка проекта
  3. В терминале вводим команду git clone [скопированная ссылка]

Так как репозиторий клонируется, то связь устанавливается как с репозиторием, так и с веткой/ветками

Коммит

Коммит — это фиксация истории проекта.
Систему Git можно представить как дерево с множеством веток, причём каждая ветка состоит из множества коммитов.

"Главная ветка" — это исходная ветка, которая создаётся автоматически при инициализации репозитория. Ветки исходящие от неё будут содержать всю информацию главной ветки до момента ответления.

Git позволяет нам перемещаться по веткам и их коммитам, откатывать историю назад, создавать новые ветки из любой точки истории.

Чтобы всегда знать, где мы находимся, существует указатель HEAD. Это указатель нашего текущего положения, или точнее, указатель текущей ветки и определённого коммита, который может стать родителем следующего. Когда мы хотим вернуться к старому коммиту, мы перемещаем этот указатель к нужному коммиту. Во всех других случаях он будет указывать на последнюю ветку, которую мы создали, и на последний коммит.

Статус файлов

Файлы могут иметь статус отслеживаемые(Tracked) и неотслеживаемые(Untracked). Отслеживаемые файлы могут находиться в трёх состояниях:

  1. Изменённые (Modified)
  2. Неизменённые (Unmodified)
  3. Подготовленные (Staged)

Чтобы узнать текущий статус файлов, используйте команду: git status

Если выводятся файлы, выделенные красным — значит есть новые изменения, которые не добавлены. Иначе говоря — есть не отслеживаемые Git файлы.

Если файлы выводятся зеленым — недавно измененные файлы добавлены. Иначе говоря — все файлы отслеживаются Git.

Если нет подсвеченных файлов и надпись такого плана: "nothing to commit, working tree clean" — значит новых не внесенных изменений нет. Все файлы отслеживаются Git.

Помимо команды "status", состояние файлов можно узнать с помощью VS Code в проводнике или во вкладке Гит. У неотслеживаемых файлов будет стоять буква "U", а у измененных "M"

Для того чтобы сохранить новое состояние файлов, их нужно проиндексировать, то есть отправить в обслать Staging Area. Для этого используем команду git add [имя_файла.расширение], если хотим проиндексировать конкретный файл, либо команду git add -A, которая проиндексирует все измененные файлы.

Поиндексировать файл также можно во вкладке гит в VS Code, нажав плюс напротив файла, либо нажав плюс в графе изменения, тогда все перечисленные файлы будут проиндексированы.

После индексации, нужно провести фиксацию (закоммитить), то есть отправить данные в локальный репозиторий, и создать запись в истории проекта. Используется команда git commit -m "описание коммита"(кавычки обязательно), либо нажав кнопку "Фиксация" во вкладке Гит в редакторе, предварительно написав сообщение в графе над кнопкой.
